# Переделка прогресса: руда вместо звёзд

Документ для новой сессии. Всё ниже обсуждено и согласовано с владельцем игры 23.10.2026.
В игре пока **ничего не переделано** — это план и данные для работы. Общая памятка проекта — `CLAUDE.md`.

---

## 1. Суть

Звёзды убираем полностью. Прогресс игрока — **добытая руда**. Рудник (зона, как area в Royal Match)
состоит из глубин; на каждой глубине игрок проходит процедурно сгенерированные уровни, добывает руду
из конечной жилы, обустраивает рудник и улучшает бур, чтобы спуститься глубже. На последней глубине —
босс; после него открывается следующий рудник. В пройденные рудники не возвращаемся.

## 2. Согласованные решения

### Руда
- **Две руды:**
  - **общая** (железо) — одна на всю игру, копится и переходит из рудника в рудник.
    Тратится на бур (спуск на следующую глубину) и на открытие следующего рудника;
  - **местная** — своя у каждого рудника (по теме рудника: Old Adit — золото, Copper Mountain — медь, Fire Horizon — сера; решено 25.10).
    Тратится только на задачи обустройства этого рудника. Остаток после босса автоматически продаётся за монеты.
- В панели ресурсов вместо звезды — 2 иконки руды (общая + местная текущего рудника).
- **На поле:** у фишки есть цвет (по нему собираются ряды, как сейчас) и независимый признак «рудная».
  Каждый рудник задаёт, у каких двух цветов есть руда (напр. в 1-м: красный → железо, жёлтый → золото).
  Рудный камень даёт **1 руду**. Плотность постоянная — рудный каждый ~2–3-й камень своего цвета.
- Рудные камни должны читаться сразу, но цвет — оставаться главным: тот же спрайт с прожилками / вкраплениями.
  **Вид рудной фишки один на все рудники** — не цвет настоящей руды, а знак «здесь руда»: местная руда —
  светящиеся золотистые жилы с самородками (`<name>_ore.png`), общая (железо) — вросшие стальные кубики
  (`<name>_iron.png`); см. «Фишки» в `CLAUDE.md`. **Какую местную руду даёт фишка — решает рудник**, а не фишка:
  в Old Adit те же жилы дают золото, в Copper Mountain — медь, в Fire Horizon — серу.
- Руда **засчитывается только при победе**. Поражение — ничего. (Позже — улучшение техники «при поражении
  сохраняется ~10% руды».)
- Цели «собрать N руды» **нет**: цели уровня остаются классическими (порода, грязь, находка, газ…),
  руда идёт попутно. Во время уровня в шапке — счётчик добытой руды.

### Жилы и глубины
- У каждой глубины **конечный запас** каждой из двух руд. **10% запаса неистощимы**: когда остаётся 10%,
  жила перестаёт убывать, но плотность руды падает **втрое**.
- Нужен **индикатор истощения жилы** (на экране рудника и в шапке уровня), напр. «Жила 62/100».
- **70% добычи рудника должно хватать**, чтобы пройти его целиком. Остальное — запас на неудачные траты.
- **Рудник = несколько глубин** (1-й ~6, 2-й 8–9, дальше 10–15). **Каждая глубина ≈ 3–4 победы**,
  почти постоянно по руднику (3 → 4), чтобы ритм «стройка — спуск» был ровным.
- **Открыть глубину N+1** = железо + монеты (бур) **+ выполненная задача обустройства глубины N** (за местную руду).
  Каждой глубине — **одна обязательная задача** (расчистить завал, крепь, фонари, рельсы…). **Необязательных задач нет.**
- **Уровни генерируются процедурно** на каждой глубине, их можно переигрывать сколько угодно.
  Сложность растёт с глубиной (новый блокер/условие примерно раз в 3–4 глубины), не с номером захода.
- **Богатые уровни:** примерно каждый 5–6-й, случайно, с гарантией (шанс растёт, если давно не было).
  Плотность руды ×2 (в пределах жилы). На жиле у отметки 10% не выпадают.
  Перед стартом — карточка «Rich vein!», на поле заметно больше рудных камней.

### Босс и рудники
- На последней глубине — **босс** (динамически меняющееся поле; проработаем отдельно, **пока не делаем**).
- Победа над боссом: **9 жеод, выбрать 1** (как открытие пака) — крутой минерал.
- После босса за монеты + общую руду открывается следующий рудник.

### Остаётся как есть
- **Жизни.**
- **Монеты:** за победу в уровне + продажа минералов.
- **Минералы:** обычные (на продажу) встречаются в уровнях; крутые — с малой вероятностью; после босса — что-то классное.
  Редкие дорогие находки (5000–12000 монет) **оставляем как джекпот**, без ограничений.
- Убрать звёзды надо **везде**, включая сундук рудника и окно победы.

## 3. Числа (из симуляции, прикидочные)

Симуляция: `godot/tests/sim_economy.gd` (см. раздел 6). Игрок в ней ходит случайно (спецфишки в приоритете) —
слабее живого; живой выигрывает чаще и получает финальный динамит за оставшиеся ходы, так что реальный выход руды
чуть выше. Подстраивается плотностью руды.

**Выход камней:** за победу разбивается **~30 камней одного цвета**, почти независимо от глубины.
При рудном каждом 2–3-м — **~12 руды каждого вида за победу**.

**Доход с минералов** (200 уровней на глубину, только построение уровней):

| Старая глубина | Уровней с находкой | Цена находки сред. / медиана / макс | Жеод за уровень | Камень из жеоды, сред. |
|---|---|---|---|---|
| 0 | 83% | 284 / 105 / 7098 | 0,45 | 283 |
| 1 | 83% | 359 / 140 / 6612 | 0,45 | 722 |
| 2 | 83% | 497 / 253 / 5380 | 0,45 | 557 |
| 3 | 83% | 827 / 296 / 12580 | 0,45 | 1120 |

Победа сама даёт ~50–100 монет (`20 + 5 × оставшиеся ходы`, × множитель глубины) — минералы в 5–10 раз доходнее.

**Правила цен:**
- задача обустройства ≈ **57%** местной жилы глубины;
- бур ≈ **60%** железной жилы глубины + монеты ≈ **60% дохода за глубину при продаже половины находок**
  (без продажи минералов бур не купить — продать/оставить становится реальным выбором);
- запас глубины ≈ (победы × выход) / 0,7.

## 4. Как устроено сейчас (что придётся менять)

- **Сохранение** `godot/scripts/autoload/save_game.gd`: `stars`, `level` (сквозной номер уровня), `area`,
  `built[area]` (выполненные задачи), `depth[area]` (открытая глубина), `depth_sel[area]`, `eq` (снаряжение),
  `coll` (коллекция минералов), `uid`. Добавить: обе руды, запасы жил по глубинам текущего рудника, счётчик «богатого» уровня.
- **Данные** `godot/data/game_data.json` (+ `scripts/autoload/data.gd`):
  `AREAS` (рудник: название, `pool` минералов, `tasks` = [id, текст, цена в звёздах]),
  `DEPTHS` (сейчас 5 глобальных: `m`, `tool`, `cost`), `DMODS`/`DSHORT` (что меняется на глубине),
  `LEVELS` (30 ручных уровней; дальше `Data.level_def` их ремиксует), `EQUIP`, `PRE`/`BOOSTS`.
  Нужно: глубины — внутри рудника, со своими запасами, ценами бура, задачей, цветами руды.
- **Модель поля** `godot/scripts/core/board_model.gd`: `setup(level_n, pre, dl, eq, area)` строит уровень из `LEVELS`;
  класс `Gem` (`t` цвет, `sp` спецфишка, `item`) — сюда флаг руды; `remove_dead()`/`run_blast()` — где засчитывать
  разбитые рудные камни; цвета: индекс в `BoardSprites.GEMS` = ruby(0, красный), sapphire(1), emerald(2, зелёный),
  citrine(3), amethyst(4), diamond(5).
- **Уровень** `godot/scripts/game/level.gd`: HUD (цели, ходы), победа (`Save.d.stars += 1` около строки 640, монеты),
  `_render_hud()`; поле — `board_view.gd`, фишка — `gem_node.gd` (спрайты `BoardSprites`).
- **Звёзды в интерфейсе:** `chrome.gd` (панель ресурсов `top_bar`), `home.gd` (задачи рудника, окно задач, сундук),
  `main.gd` (`_win_card` — «★ +1»), `level.gd` (заголовок «· ★» для сложных уровней — это не звёзды-валюта).
- **Главный экран рудника** `home.gd` + `mine_scene.gd` (рисует 5 полос-глубин, постройки по `built`).
  Нужна шахта на 6–15 глубин с прокруткой.
- **Депо** `depot.gd`: вкладка «Sinking» — покупка бура за монеты (`Data.depth_cost`), вкладка «Gear» — снаряжение.
  Бур переезжает в механику глубин (железо + монеты + задача).

## 5. План (каждый шаг — отдельная сборка, проверять на iPhone)

1. **Данные и экономика:** руды в сохранении; описание рудника 1 (6 глубин: запасы, цены бура, задача, цвета руды)
   по таблице выше; убрать звёзды из сохранения и интерфейса; панель ресурсов — руды вместо звезды; миграция старых сохранений.
2. **Руда на поле:** флаг у фишки с плотностью, засчитывание при победе, счётчик в шапке уровня, индикатор жилы;
   рудные спрайты (Blender) для двух цветов.
3. **Экран рудника:** глубины с задачами и буром; карточка «что нужно для следующей глубины» с галочками
   («Железо 18/30 · Монеты ✓ · Завал ✗»); переигрывание открытых глубин.
4. **Генератор уровней по глубине** (раскладка, блокеры, цели, ходы по сложности; проверять автоигроком) + богатые уровни.
5. **Босс** — отдельно, потом.

После каждого шага — прогон `sim=` / `sim_min=` (раздел 6), сверка с таблицей.

## 6. Инструменты

- Отладочные ключи (`godot/scripts/main.gd`, после `--`): `level=N`, `depth=D`, `screen=depot|museum`, `reveal=<seed>`,
  `legend=<fx>`, `autoplay=N`, `win`, `fill=14`, `shot=user://x.png after=S`, `hitch=S` (лог медленных кадров),
  `enter=S` (зайти в уровень с главного), `notch=59,34` (имитация выреза iPhone), `sim=N` (N уровней на глубину,
  разбитые камни по цветам), `sim_min=N` (доход с минералов), `stress=N`, `bake_thumbs`, `bake_boot`.
- `sim=25` идёт ~1 минуту, `sim_min=200` — секунды. **Гонять маленькими выборками** — длинные прогоны владелец прерывает.
- Диагностика на телефоне: зажать кнопку ♪ ~1 с → журнал (ошибки, медленные кадры, FPS/CPU/GPU) → Copy.
- Сборка: push в `main` → GitHub Actions собирает `.ipa` (~10 мин), шейдеры запекаются при экспорте (`shader_baker`).

## 7. Уроки прошлых сессий (iPhone)

- На ПК всё может работать, а на iPhone нет: проверять каждую сборку на телефоне, просить журнал Diag.
- После запекания шейдеров стандартный шейдер Godot для спрайтов на iPhone **не рисовал фишки** —
  у фишек свой шейдер (`gem_glint`, блик выключен). Не убирать.
- Постройка 3D-образцов идёт по одной через очередь (`SpecStudio.build_async`), без мьютекса внутри потока —
  иначе одна ошибка вешала все следующие постройки и потоки движка.
- Генератор минералов (`godot/scripts/specimen/`) — стиль утверждён, не трогать без запроса;
  вид старых камней сохранять не нужно — игроков нет.
